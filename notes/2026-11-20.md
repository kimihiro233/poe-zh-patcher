### 发布（v0.7.0）

- `dotnet publish -c Release -r win-x64 --self-contained` → `dist/PoE-zh-Patcher.exe`（43.0 MB）
- `python tools/release.py --note "…"` → `releases/poe-zh-v0.7.0+game3.30.0d.zip`（36.4 MB）
  + `releases/v0.7.0/`（文档 + 12 份修正稿 + 3 份词缀清单 + BUILD-INFO + SBOM + MANIFEST.sha256）
- 提交 `bfc53e6`（适配）、`03f759d`（发布快照），tag `v0.7.0`
- **推送又撞上 HTTP 408**（代理对大包上传会掉速）。`-c http.version=HTTP/1.1` 这次**没用**，
  有效的是**分段推**：先单独推体积最大的那个提交（`git push origin bfc53e6:master`），
  再推剩下的（`git push origin master`）+ tag，一次一个就都过了。
  —— 上一轮记的「分段推」到今天才真正用上，结论：**一次只推一个提交**。
- 发布流程的坑（与上一轮相同）：publish 会把 `tools/dropper/packages.lock.json`
  改成 RID 版本 → 工作树脏 → `release.py` 拒绝打包。发布后
  `git checkout -- tools/dropper/packages.lock.json` 还原即可。
